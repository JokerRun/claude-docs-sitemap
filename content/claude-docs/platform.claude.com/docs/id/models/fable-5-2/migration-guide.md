Biarkan Claude Code memigrasikan kode Anda

```text
/claude-api migrate proyek ini ke claude-fable-5-2
```

Jika agen Claude Managed Agents Anda memiliki advisor, `model` milik advisor adalah nama model kedua yang perlu diperbarui: atur ke `claude-fable-5-2` atau `claude-mythos-5-2` saat Anda mengubah model agen. Lihat [Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-advisor-pairs). Jika objek `model` agen mengatur `speed: "fast"`, hapus juga pengaturan tersebut.

Bagian-bagian berikut membahas perpindahan ke Claude Fable 5.2, atau ke Claude Mythos 5.2, dari Claude Fable 5.1, Claude Mythos 5.1, Claude Opus 5.5, atau model Claude Fable, Claude Mythos, atau Claude Opus yang lebih lama. Untuk perubahannya sendiri, lihat [Yang baru di Claude Fable 5.2](https://platform.claude.com/docs/id/models/fable-5-2/whats-new-fable-5-2). Untuk perbedaan perilaku dan pola prompting khusus model, lihat [Prompting Claude Fable 5.2](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2).

Claude Fable 5.2 tersedia di Claude API, [Amazon Bedrock (`bedrock-runtime`)](https://platform.claude.com/docs/id/build-with-claude/claude-on-amazon-bedrock-legacy), [Claude Platform on AWS](https://platform.claude.com/docs/id/build-with-claude/claude-platform-on-aws), [Claude Models on Google Cloud (Anthropic managed)](https://platform.claude.com/docs/id/build-with-claude/claude-models-on-google-cloud/anthropic-managed), [Claude Models on Google Cloud (Google managed)](https://platform.claude.com/docs/id/build-with-claude/claude-models-on-google-cloud/google-managed), dan [Microsoft Foundry](https://platform.claude.com/docs/id/build-with-claude/claude-in-microsoft-foundry). [Claude Mythos 5.2](https://platform.claude.com/docs/id/models/mythos-5-2/overview) memiliki kemampuan yang sama dan hanya tersedia bagi organisasi yang telah diverifikasi melalui program verifikasi Anthropic, seperti [Cyber Verification Program](https://support.claude.com/en/articles/14604842).

Pengaturan dasar yang sama untuk `claude-fable-5-2` dan `claude-mythos-5-2`:

* **Thinking:** [Adaptive thinking](https://platform.claude.com/docs/id/build-with-claude/thinking) (pemikiran adaptif) selalu aktif, tidak berubah dari Claude Fable 5.1. Model menentukan kapan dan seberapa banyak berpikir, dan parameter [effort](https://platform.claude.com/docs/id/build-with-claude/effort) mengontrol seberapa dalam. Baik `thinking: {type: "disabled"}` maupun pemikiran diperpanjang manual (`thinking: {type: "enabled", budget_tokens: N}`) mengembalikan error 400.
* **Effort:** Kelima level [effort](https://platform.claude.com/docs/id/build-with-claude/effort) didukung, dan defaultnya adalah `high`, tidak berubah dari Claude Fable 5.1. Lihat [Level effort yang direkomendasikan untuk Claude Fable 5.2](https://platform.claude.com/docs/id/build-with-claude/effort#recommended-effort-levels-for-claude-fable-5-2).
* **Prefill:** “Prefilling” (pengisian awal) pesan asisten mengembalikan error 400, tidak berubah dari Claude Fable 5.1. Gunakan instruksi prompt sistem sebagai gantinya.
* **Parameter sampling:** Hilangkan `temperature`, `top_p`, dan `top_k`, seperti pada Claude Fable 5.1. Lihat [Parameter sampling](https://platform.claude.com/docs/id/build-with-claude/thinking#sampling-parameters) untuk nilai-nilai yang mengembalikan error 400.
* **Tool choice:** `{type: "auto"}` (default) dan `{type: "none"}` didukung. Memaksa pemanggilan alat dengan `{type: "any"}` atau `{type: "tool", name: "..."}` mengembalikan error 400, tidak berubah dari Claude Fable 5.1.
* **Output terstruktur:** Dalam organisasi dengan [“customer-managed encryption keys” (kunci enkripsi yang dikelola pelanggan)](https://platform.claude.com/docs/id/manage-claude/cmek), atau CMEK, [output terstruktur](https://platform.claude.com/docs/id/build-with-claude/structured-outputs) tidak tersedia untuk kedua model, sama seperti Claude Fable 5.1. Hal ini mencakup penggunaan alat ketat maupun output JSON. Jika permintaan Anda mengatur `strict: true` atau `output_config.format` di sana, hapus keduanya dan validasi output di kode Anda.
* **Pemikiran yang dipertahankan lintas model:** Di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 dan Claude Mythos 5.2 dapat membaca blok thinking satu sama lain serta blok dari model lain, termasuk Claude Opus 5.5, Claude Sonnet 5.5, dan Claude Haiku 5.5. Tidak ada model lain yang dapat membaca blok mereka. Lihat [Beralih model di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#switching-models) untuk daftarnya.
* **Thinking yang terikat akun:** Blok thinking dari Claude Fable 5.2 dan Claude Mythos 5.2 hanya berfungsi di akun yang menghasilkannya, atau di akun yang tertaut dengannya. Ketika akun lain mengirim salah satu blok ini, API membuang blok tersebut sebelum model menerimanya, dan permintaan berhasil. Di Claude API dan Claude Models on Google Cloud (Google managed), dengan header beta `thinking-binding-controls-2026-08-01`, respons mencantumkan setiap blok yang dibuang di `input_transformations` dengan `reason: "organization_binding_mismatch"`. Lihat [Blok pemikiran tetap berada di akun yang menghasilkannya](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#account-bound-thinking).
* **Jendela konteks dan output:** “Context window” (jendela konteks) sebesar [1M token](https://platform.claude.com/docs/id/build-with-claude/context-windows) secara default, dan hingga 128k token output untuk setiap permintaan.
* **Harga:** $8 USD per juta token input dan $40 USD per juta token output, dibandingkan dengan $10 USD dan $50 USD pada Claude Fable 5.1 dan Claude Mythos 5.1. Pembacaan cache prompt seharga $0,20 USD per juta token, dibandingkan dengan $0,25 USD pada model-model tersebut. Lihat [Harga](https://platform.claude.com/docs/id/about-claude/pricing).
* **Retensi data:** Kedua model memerlukan retensi data 30 hari, tidak tersedia di bawah pengaturan “zero data retention” (retensi data nol), atau ZDR, kecuali diizinkan secara tegas oleh Anthropic, dan ditetapkan sebagai Covered Models, sama seperti Claude Fable 5.1 dan Claude Mythos 5.1. Di Claude API, permintaan dari organisasi atau workspace tanpa retensi 30 hari mengembalikan `invalid_request_error` 400. Organisasi dengan pengaturan ZDR harus menghubungi tim akun Anthropic mereka, atau mengonfigurasi retensi untuk workspace individual. Lihat [Persyaratan retensi data khusus model](https://platform.claude.com/docs/id/manage-claude/api-and-data-retention#model-specific-data-retention-requirements) untuk detail per platform.
* **Priority Tier:** Kedua model tidak didukung di [Priority Tier](https://platform.claude.com/docs/id/api/service-tiers#supported-models).
* **Mode cepat:** Kedua model mendukung [mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode) dalam permintaan Messages API. [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan platform untuk setiap model.

Di mana kedua model berbeda:

* **Ketersediaan:** Di Claude API, Claude Fable 5.2 tidak memerlukan persetujuan akses. Claude Mythos 5.2 hanya tersedia bagi organisasi yang telah diverifikasi melalui program verifikasi Anthropic, seperti [Cyber Verification Program](https://support.claude.com/en/articles/14604842). Untuk meminta akses, daftarlah ke program yang mencakup kasus penggunaan Anda, atau hubungi tim akun Anthropic Anda.
* **Batas laju:** Claude Fable 5.2 memiliki “rate limit” (batas laju) sendiri, terpisah dari batas gabungan yang digunakan bersama oleh Claude Fable 5.1 dan Claude Fable 5. Claude Mythos 5.2 berbagi satu batas gabungan dengan Claude Mythos 5.1 dan Claude Mythos 5. Lihat [Batas laju](https://platform.claude.com/docs/id/api/rate-limits#rate-limits).

## Migrasi ke Claude Fable 5.2 dari Claude Fable 5.1

Migrasi sebagian besar bersifat drop-in. Permukaan API, adaptive thinking yang selalu aktif, pembatasan tool choice paksa, penanganan penolakan, kategori `stop_details`, dan persyaratan retensi data semuanya sama dengan Claude Fable 5.1. Claude Fable 5.2 lebih murah: $8 USD per juta token input dan $40 USD per juta token output, dibandingkan dengan $10 USD dan $50 USD pada Claude Fable 5.1. Empat perubahan dapat merusak kode Anda. [Pemeriksaan prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#prefix-check), yang mendeteksi pengeditan pada giliran sebelumnya, berlaku untuk setiap akun. Claude Fable 5.1 tidak dapat membaca blok thinking Claude Fable 5.2. Alat computer use yang lebih lama, `computer_20251124`, mengembalikan error 400 di setiap platform kecuali Amazon Bedrock. Dengan alat advisor, executor Claude Fable 5.2 hanya menerima Claude Fable 5.2 atau Claude Mythos 5.2 sebagai advisor-nya.

### Perbarui nama model Anda

```python
model = "claude-fable-5-1"  # Before
model = "claude-fable-5-2"  # After
```

ID model adalah `claude-fable-5-2` di setiap platform kecuali Amazon Bedrock. Di sana, ID-nya adalah `global.anthropic.claude-fable-5-2` atau `us.anthropic.claude-fable-5-2`, dan hanya endpoint `bedrock-runtime` yang melayani model tersebut.

### Perubahan yang merusak kompatibilitas

1. **Pemeriksaan prefiks berlaku untuk setiap akun:** Setiap blok `thinking` dari Claude Fable 5.2 hanya valid terhadap prompt `system`, `tools`, dan riwayat percakapan yang mendahuluinya, seperti pada Claude Fable 5.1. Claude Fable 5.2 memberlakukan [pemeriksaan prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#prefix-check) ini untuk setiap akun, berapa pun usianya. Claude Fable 5.1 memberlakukannya secara default untuk akun yang dibuat pada atau setelah 31 Agustus 2026. Jadi pada akun yang lebih lama, permintaan yang lolos di Claude Fable 5.1 dapat gagal di Claude Fable 5.2.

   Tidak ada yang berubah bagi Anda jika Claude Code, claude.ai, [Claude Managed Agents](https://platform.claude.com/docs/id/managed-agents/overview), atau [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) yang mengelola riwayat percakapan Anda. Jika kode Anda membangun array `messages` sendiri, bandingkan apa yang dilakukannya di antara permintaan dengan daftar di [Siapa yang terpengaruh oleh pemeriksaan prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#who-is-affected). Permintaan yang mengirim kembali blok thinking setelah salah satu pengeditan tersebut mengembalikan error 400:

   ```text wrap
   messages.5.content.0: Invalid `signature` in `thinking` block. The block is bound to a different conversation. Remove the block, or set `thinking.block_binding.prefix_mismatch_behavior` to "drop_block". That setting requires the `thinking-binding-controls-2026-08-01` value in the `anthropic-beta` header.
   ```

   Mencoba ulang badan permintaan yang sama tidak menghilangkan error tersebut. Untuk menemukan pengeditan ini sebelum Anda memindahkan lalu lintas produksi, jalankan pemeriksaan di [Periksa apakah kode Anda mengedit prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#how-to-tell-whether-your-integration-is-impacted) terhadap model yang Anda gunakan saat ini, Claude Fable 5.1 atau Claude Opus 5.5. Jika Anda menggunakan [konektor MCP](https://platform.claude.com/docs/id/agents-and-tools/mcp-connector) tanpa [menyematkan daftar alat server](https://platform.claude.com/docs/id/agents-and-tools/mcp-connector#pin-mcp-tool-list), jalankan juga pemeriksaan terhadap `claude-fable-5-2`: daftar alat yang berubah di antara permintaan merupakan pengeditan bagi blok thinking Claude Fable 5.2, tetapi tidak bagi blok Claude Fable 5.1 atau Claude Opus 5.5. Pemeriksaan ini berfungsi dari akun mana pun, karena mengatur `prefix_mismatch_behavior` membuat permintaan ikut serta dalam pemeriksaan. [Pemikiran yang dipertahankan](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking) memberikan perbaikan untuk setiap pola.

   Di produksi, biarkan `prefix_mismatch_behavior` pada nilai defaultnya, `"error"`, jika ketidakcocokan hanya dapat berarti bug di kode Anda. Untuk membuang blok yang terpengaruh dan melanjutkan tanpa penalaran tersebut selagi Anda memperbaiki pengeditan, atur ke `"drop_block"`. Perlakukan itu sebagai solusi sementara, bukan pengaturan jangka panjang: [membuang blok dapat menaikkan token output](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#drop-block-cost).

2. **Claude Fable 5.1 tidak dapat membaca blok thinking Claude Fable 5.2:** Di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 dapat membaca blok Claude Fable 5.1, sehingga percakapan yang berpindah dari `claude-fable-5-1` ke `claude-fable-5-2` mempertahankan penalaran sebelumnya. Ke arah sebaliknya, Claude Fable 5.1 tidak dapat membaca blok Claude Fable 5.2. Jika peralihan router, percobaan ulang sisi klien, atau [fallback penolakan classifier](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback) memindahkan percakapan dari Claude Fable 5.2 ke model lain, termasuk Claude Fable 5.1, API membuang blok yang tidak dapat dibaca model tersebut. Permintaan berhasil, dan Anda tidak ditagih untuk token input yang dibuang. Model kemudian bekerja tanpa penalaran tersebut, yang dapat menaikkan biaya dan latensi pada giliran pertama setelah peralihan. Dengan header beta `thinking-binding-controls-2026-08-01`, `input_transformations` mencantumkan setiap blok yang dibuang dengan `reason: "model_binding_mismatch"`. Lihat [Beralih model di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#switching-models).

3. **Gunakan toolset computer use sebagai pengganti `computer_20251124`:** Entri `tools` dengan tipe `computer_20251124` mengembalikan error 400 di setiap platform kecuali Amazon Bedrock. Deklarasikan toolset `computer_toolset_20260801` sebagai gantinya: hapus header beta dan kirim entri tanpa `name` atau dimensi tampilan. Kemudian perbarui loop agen Anda untuk toolset tersebut, seperti yang dijelaskan di [Migrasi dari `computer_20251124`](https://platform.claude.com/docs/id/agents-and-tools/tool-use/computer-use-tool#migrate-from-computer-20251124). Di Amazon Bedrock, Claude Fable 5.2 dan Claude Mythos 5.2 menerima alat yang lebih lama: dengan InvokeModel API, kirim `computer-use-2025-11-24` dalam array `anthropic_beta` pada badan permintaan.

4. **Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2:** Dengan [alat advisor](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool), yang masih dalam tahap beta, advisor harus setidaknya sama mampunya dengan executor. Executor Claude Fable 5.2 atau Claude Mythos 5.2 hanya menerima Claude Fable 5.2 atau Claude Mythos 5.2 sebagai advisor-nya, dan advisor lain apa pun, termasuk Claude Fable 5.1 dan Claude Mythos 5.1, mengembalikan `invalid_request_error` 400. Saat Anda mengubah ID model executor, atur `model` dalam definisi alat advisor ke `claude-fable-5-2` atau `claude-mythos-5-2`. Mengubah `model` advisor merupakan pengeditan pada `tools`, jadi lakukan perubahan tersebut di percakapan baru. Permintaan yang mengirim kembali blok thinking sebelumnya setelah perubahan akan gagal dalam pemeriksaan prefiks (lihat [Pemeriksaan prefiks berlaku untuk setiap akun](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-preserved-thinking)) dan mengembalikan error 400, kecuali Anda mengatur `prefix_mismatch_behavior` ke `"drop_block"`. Untuk mempertahankan executor Anda saat ini dan hanya mengubah advisor, atur `model` advisor ke `claude-fable-5-2`: setiap model executor menerimanya. Advisor Claude Fable 5.2 mengembalikan sarannya dalam bentuk terenkripsi, jadi jika kode Anda membaca teks saran, lihat [Varian hasil](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool#result-variants). Pasangan yang sama berlaku untuk advisor agen [Claude Managed Agents](https://platform.claude.com/docs/id/managed-agents/overview), jadi atur `model` advisor tersebut ke salah satu dari dua model ini saat Anda mengubah model agen. Lihat [Kompatibilitas model](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool#model-compatibility) dan [Berikan advisor pada sesi](https://platform.claude.com/docs/id/managed-agents/multiagent-orchestration#give-the-session-an-advisor).

### Perubahan perilaku

1. **Baris prompt yang meminta lebih sedikit berpikir tidak menghentikan model dari berpikir pada effort `medium` ke atas:** Claude Fable 5.1 biasanya mengikuti baris seperti “jawab langsung tanpa berunding.” Dalam pengujian Anthropic, baris seperti itu tidak menghentikan Claude Fable 5.2 dari berpikir pada `medium` ke atas. Hapus baris-baris ini dan turunkan level effort. Lihat [Kalibrasi effort](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#calibrate-effort).
2. **Model dapat memulai subagen untuk meninjau pekerjaannya sendiri pada effort yang lebih tinggi:** Dalam produk coding agentik pada level effort yang lebih tinggi, seperti `xhigh` dan `max`, Anthropic mengamati Claude Fable 5.2 menggunakan subagen untuk meninjau pekerjaannya sendiri. Claude Fable 5.1 tidak melakukan ini pada tugas yang sama. Subagen dapat menyumbang sebagian besar biaya sebuah sesi. Lihat [Tetapkan ekspektasi untuk subagen](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#set-expectations-for-subagents).
3. **`max_tokens` yang kecil dapat tidak menyisakan ruang untuk teks:** Token thinking dihitung dalam `max_tokens`, sehingga permintaan dengan `max_tokens` kecil dapat berhenti dengan `stop_reason: "max_tokens"` setelah blok `thinking` dan sebelum teks apa pun. Baris prompt yang biasanya mencegah Claude Fable 5.1 berpikir tidak mencegah Claude Fable 5.2 berpikir pada effort `medium` ke atas. Jadi permintaan yang mengandalkan baris seperti itu agar muat dalam `max_tokens` kecil di Claude Fable 5.1 dapat kehabisan token sebelum menghasilkan teks apa pun di Claude Fable 5.2. Naikkan `max_tokens` untuk menyisakan ruang bagi thinking, atau pilih level [effort](https://platform.claude.com/docs/id/build-with-claude/effort) yang lebih rendah.

Untuk perilaku lain yang perlu diperiksa saat Anda membawa prompt, lihat [Perbedaan perilaku](https://platform.claude.com/docs/id/models/fable-5-2/whats-new-fable-5-2#behavior-differences).

### Daftar periksa migrasi

* Perbarui nama model dari `claude-fable-5-1` ke `claude-fable-5-2`.
* Periksa [batas laju](https://platform.claude.com/docs/id/api/rate-limits#rate-limits) Anda sebelum memindahkan lalu lintas produksi. Claude Fable 5.2 memiliki batas lajunya sendiri, terpisah dari yang digunakan bersama oleh Claude Fable 5.1 dan Claude Fable 5.
* Jika Anda menggunakan computer use melalui `computer_20251124` di mana pun kecuali Amazon Bedrock, Claude Fable 5.2 mengembalikan error 400 untuk alat tersebut. Deklarasikan `computer_toolset_20260801` sebagai gantinya dan perbarui loop agen Anda untuk toolset tersebut.
* Jika Anda menggunakan alat advisor dengan Claude Fable 5.2 sebagai executor, atur `model` advisor ke `claude-fable-5-2` atau `claude-mythos-5-2`.
* Jika kode Anda membangun array `messages` sendiri, jalankan sesi dengan header beta `thinking-binding-controls-2026-08-01` dan `prefix_mismatch_behavior: "drop_block"`, catat `input_transformations`, dan perbaiki setiap entri `prefix_binding_mismatch`. Lakukan ini bahkan jika akun Anda tidak pernah terkena pemeriksaan di Claude Fable 5.1.
* Pilih `prefix_mismatch_behavior` untuk produksi: `"error"` (default), atau `"drop_block"` sebagai solusi sementara selagi Anda memperbaiki pengeditan, karena [membuang blok dapat menaikkan token output](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#drop-block-cost). Pantau error 400 atau entri `input_transformations`.
* Tetap kirim kembali blok `thinking` tanpa perubahan di setiap giliran, termasuk yang kosong. Jika router atau fallback dapat memindahkan percakapan dari Claude Fable 5.2 ke Claude Fable 5.1, perkirakan Claude Fable 5.1 berjalan tanpa blok Claude Fable 5.2.
* Jika Anda memutar ulang percakapan tersimpan melalui akun yang berbeda, putar ulang masing-masing melalui akun yang menghasilkannya, atau akun yang tertaut dengannya. API membuang blok thinking Claude Fable 5.2 yang dihasilkan akun lain. Lihat [Blok pemikiran tetap berada di akun yang menghasilkannya](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#account-bound-thinking).
* Jalankan ulang [sweep effort](https://platform.claude.com/docs/id/build-with-claude/effort#recommended-effort-levels-for-claude-fable-5-2) pada eval Anda sendiri, dan tetapkan ulang baseline biaya dan latensi.
* Periksa prompt sistem, skill, dan instruksi lain yang Anda bawa terhadap [Tinjau prompt dan harness yang dirancang untuk model sebelumnya](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#review-instructions-written-for-earlier-models).

## Migrasi ke Claude Mythos 5.2 dari Claude Mythos 5.1

## Migrasi ke Claude Fable 5.2 dari Claude Opus 5.5

Claude Fable 5.2 menggunakan Messages API dan pola penggunaan alat yang sama dengan [Claude Opus 5.5](https://platform.claude.com/docs/id/models/opus-5-5/overview). Kedua model selalu berpikir secara adaptif dan mengembalikan error 400 untuk tool choice paksa, sehingga bagian-bagian permintaan Anda tersebut tetap berlaku. Perbedaan berikut berlaku saat Anda memindahkan lalu lintas, atau jalur fallback, ke Claude Fable 5.2.

### Perbarui nama model Anda

```python
model = "claude-opus-5-5"  # Before
model = "claude-fable-5-2"  # After
```

### Apa yang berubah

1. **Retensi data diperlukan:** Claude Fable 5.2 memerlukan retensi data 30 hari dan tidak tersedia di bawah pengaturan zero data retention (ZDR) kecuali diizinkan secara tegas oleh Anthropic. Jika organisasi atau workspace Anda menjalankan Claude Opus 5.5 di bawah ZDR, aktifkan retensi 30 hari untuk sebuah workspace atau hubungi tim akun Anthropic Anda sebelum beralih. Jika tidak, di Claude API, setiap permintaan ke Claude Fable 5.2 mengembalikan `invalid_request_error` 400. Lihat [Persyaratan retensi data khusus model](https://platform.claude.com/docs/id/manage-claude/api-and-data-retention#model-specific-data-retention-requirements).

2. **Pemeriksaan prefiks berlaku untuk setiap akun:** Claude Opus 5.5 memberlakukan pemeriksaan prefiks secara default untuk akun yang dibuat pada atau setelah 31 Agustus 2026. Claude Fable 5.2 memberlakukannya untuk setiap akun, berapa pun usianya. Jika akun Anda lebih lama dan kode Anda mengubah `system`, `tools`, atau pesan sebelumnya di antara permintaan, permintaan yang berfungsi di Claude Opus 5.5 dapat gagal di Claude Fable 5.2. Untuk menguji sebelum beralih, lihat [Pemeriksaan prefiks berlaku untuk setiap akun](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-preserved-thinking).

3. **Claude Opus 5.5 tidak dapat membaca blok thinking Claude Fable 5.2:** Percakapan yang berpindah dari Claude Fable 5.2 ke Claude Opus 5.5 mempertahankan teks dan pemanggilan alatnya, tetapi giliran setelah peralihan berjalan tanpa penalaran Claude Fable 5.2. API membuang blok-blok tersebut sebelum model menerimanya, permintaan berhasil, dan blok yang dibuang tidak ditagih. Perkirakan biaya dan latensi yang lebih tinggi pada giliran pertama setelah peralihan. Ke arah sebaliknya, di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 dapat membaca blok thinking Claude Opus 5.5, sehingga percakapan yang berpindah dari `claude-opus-5-5` ke `claude-fable-5-2` mempertahankan penalaran sebelumnya.

4. **Classifier keamanan dan fallback:** Claude Fable 5.2 menjalankan classifier keamanan yang mencakup kategori `stop_details` yang sama dengan Claude Fable 5.1. Tangani setiap kategori dalam [tabel kategori penolakan](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback#refusal-response), bukan hanya yang pernah Anda lihat dari Claude Opus 5.5. Untuk menjalankan ulang permintaan yang ditolak pada model lain, atur `fallbacks: "default"`, yang mencoba ulang pada model yang direkomendasikan Anthropic untuk kategori tersebut, atau bangun mekanisme percobaan ulang Anda sendiri. Parameter tersebut masih dalam tahap beta di Claude API dan Claude Models on Google Cloud (Anthropic managed), serta memerlukan header beta `server-side-fallback-2026-07-01`. Target fallback yang diizinkan untuk Claude Fable 5.2 adalah Claude Opus 4.8 (`claude-opus-4-8`) dan Claude Opus 5 (`claude-opus-5`). Fallback sisi server tidak mencoba ulang permintaan yang ditolak dengan `"reasoning_extraction"`. Penolakan tersebut dikembalikan kepada Anda. Model fallback tidak menerima blok thinking Claude Fable 5.2. Lihat [Penolakan dan fallback](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback).

5. **Harga:** Claude Fable 5.2 berbiaya $8 USD per juta token input dan $40 USD per juta token output, dibandingkan dengan $4 USD dan $20 USD untuk Claude Opus 5.5. Pembacaan cache prompt seharga $0,20 USD per juta token pada kedua model. Lihat [Harga](https://platform.claude.com/docs/id/about-claude/pricing).

6. **Mode cepat:** Claude Fable 5.2 mendukung [mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode) (`speed: "fast"`) dalam permintaan Messages API di Claude API, seperti halnya Claude Opus 5.5. Mode cepat untuk Claude Fable 5.2 berbiaya $16 USD per juta token input dan $80 USD per juta token output, dibandingkan dengan $8 USD dan $40 USD untuk Claude Opus 5.5 dalam mode cepat. Lihat [Harga mode cepat](https://platform.claude.com/docs/id/about-claude/pricing#fast-mode-pricing).

   Claude Fable 5.2 juga mendukung mode cepat di [Claude Models on Google Cloud (Anthropic managed)](https://platform.claude.com/docs/id/build-with-claude/claude-models-on-google-cloud/anthropic-managed), dengan pengaturan `speed: "fast"` yang sama.

   Claude Fable 5.2 juga mendukung mode cepat di [Claude Models on Google Cloud (Google managed)](https://platform.claude.com/docs/id/build-with-claude/claude-models-on-google-cloud/google-managed), dengan pengaturan `speed: "fast"` yang sama. Google Cloud menetapkan harganya di sana. Lihat [Harga platform cloud](https://platform.claude.com/docs/id/about-claude/pricing#cloud-platform-pricing).

   Claude Fable 5.2 juga mendukung mode cepat di [Claude in Microsoft Foundry](https://platform.claude.com/docs/id/build-with-claude/claude-in-microsoft-foundry) untuk deployment yang di-hosting di Anthropic. Di sana, mode cepat merupakan model terpisah: kirim permintaan ke deployment `claude-fable-5-2-fast` dan jangan sertakan `speed`.

   Claude Mythos 5.2 juga mendukung mode cepat dalam permintaan Messages API di Claude API, dengan harga mode cepat Claude Fable 5.2. [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan setiap platform tempat Claude Mythos 5.2 memiliki mode cepat.

   Hapus `speed: "fast"` di Claude Managed Agents. Hapus juga di platform atau opsi hosting mana pun tempat [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) tidak mencantumkan model yang Anda tuju.

7. **Output terstruktur di organisasi CMEK:** Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), Claude Opus 5.5 mendukung [output terstruktur](https://platform.claude.com/docs/id/build-with-claude/structured-outputs) dan Claude Fable 5.2 tidak. Hapus `strict: true` dan `output_config.format` dari permintaan yang Anda pindahkan, dan validasi output di kode Anda.

8. **Effort default adalah `high`:** Claude Opus 5.5 secara default menggunakan `medium`, sehingga permintaan yang menghilangkan `effort` berjalan satu level lebih tinggi di Claude Fable 5.2. Permintaan berhasil, dan perubahan hanya terlihat sebagai perbedaan biaya, latensi, dan hasil. Atur `effort` secara eksplisit, lalu jalankan ulang [sweep effort](https://platform.claude.com/docs/id/build-with-claude/effort#recommended-effort-levels-for-claude-fable-5-2) pada eval Anda sendiri.

9. **Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2:** Dengan [alat advisor](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool), yang masih dalam tahap beta, executor Claude Opus 5.5 menerima beberapa advisor, di antaranya Claude Opus 5.5 dan Claude Fable 5.1. Lihat [Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-advisor-pairs).

## Migrasi ke Claude Fable 5.2 dari Claude Fable 5

Permukaan API, jendela konteks dan batas output, tokenizer, adaptive thinking yang selalu aktif, dan penanganan penolakan semuanya sama dengan Claude Fable 5. Beberapa perubahan berikut juga berlaku saat Anda berpindah dari Claude Mythos 5 ke Claude Mythos 5.2. [Migrasi ke Claude Mythos 5.2 dari Claude Mythos 5](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#migrating-from-claude-mythos-5-to-claude-mythos-5-2) menyebutkan yang mana saja.

### Perbarui nama model Anda

```python
model = "claude-fable-5"  # Before
model = "claude-fable-5-2"  # After
```

### Perubahan yang merusak kompatibilitas

1. **Pilihan alat paksa mengembalikan error 400:** Claude Fable 5 menerima `tool_choice` `auto`, `none`, `any`, dan `tool`. Pada `claude-fable-5-2`, `{type: "any"}` dan `{type: "tool", name: "..."}` mengembalikan 400 `invalid_request_error`, begitu pula endpoint [penghitungan token](https://platform.claude.com/docs/id/build-with-claude/token-counting). Lihat [Penggunaan alat paksa tidak didukung](https://platform.claude.com/docs/id/api/errors#forced-tool-use-not-supported) untuk pesan errornya.

   Untuk mendapatkan pemanggilan alat tanpa memaksanya, biarkan `tool_choice` pada `auto` dan sebutkan nama alat dalam instruksi Anda. Atur `strict: true` pada alat agar pemanggilannya sesuai dengan skema Anda. Lihat [Penggunaan alat ketat](https://platform.claude.com/docs/id/agents-and-tools/tool-use/strict-tool-use). Jika Anda memaksa alat hanya untuk mendapatkan JSON yang valid sesuai skema, gunakan [output JSON](https://platform.claude.com/docs/id/build-with-claude/structured-outputs#usage) sebagai gantinya. Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), [output terstruktur](https://platform.claude.com/docs/id/build-with-claude/structured-outputs) tidak tersedia untuk Claude Fable 5.2 atau Claude Mythos 5.2. Hal ini mencakup penggunaan alat ketat dan output JSON. Di sana, tetap gunakan `auto` dan instruksinya, jangan sertakan `strict`, dan validasi input alat di kode Anda.

   Jika aplikasi Anda memerlukan pemanggilan alat tertentu pada giliran saat ini, tambahkan [pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages) setelah giliran `user` terakhir. Sebutkan nama alatnya, nyatakan bahwa pemanggilan tersebut wajib untuk giliran ini, dan minta Claude untuk membuka responsnya dengan pemanggilan itu. Giliran-giliran sebelumnya tetap tidak berubah, sehingga cache hit prompt dan blok thinking-nya tetap valid. [Pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages) mencantumkan platform tempat fitur ini tersedia. Untuk giliran yang tidak boleh memanggil alat, `tool_choice: {"type": "none"}` tetap berfungsi. Lihat [Memaksa penggunaan alat](https://platform.claude.com/docs/id/agents-and-tools/tool-use/define-tools#forcing-tool-use).

2. **Mengedit giliran sebelumnya membatalkan validitas blok thinking, di setiap akun:** Claude Fable 5 tidak memeriksa apakah giliran sebelumnya berubah. Pada Claude Fable 5.2, setiap blok `thinking` hanya valid terhadap prompt `system`, `tools`, dan pesan-pesan yang datang sebelumnya. Claude Fable 5.2 memberlakukan [pemeriksaan prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#prefix-check) ini untuk setiap akun. Permintaan yang mengirimkan kembali blok thinking setelah salah satu dari elemen tersebut berubah akan mengembalikan error 400, dan mencoba ulang dengan body permintaan yang sama tidak akan menghilangkannya.

   Tidak ada yang berubah bagi Anda jika Claude Code, claude.ai, [Claude Managed Agents](https://platform.claude.com/docs/id/managed-agents/overview), atau [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) yang mengelola riwayat percakapan Anda. Jika kode Anda membangun array `messages` sendiri, pertahankan riwayat agar hanya ditambahkan (append-only). Bekukan `system` dan `tools` selama sesi. Lakukan perubahan instruksi dan alat dengan [pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages), dan pangkas konteks dengan [compaction](https://platform.claude.com/docs/id/build-with-claude/compaction) atau [pengeditan konteks](https://platform.claude.com/docs/id/build-with-claude/context-editing) di sisi server. [Pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages) mencantumkan platform tempat fitur ini tersedia. [Melakukan perubahan tanpa mengedit prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#replace-prefix-edits) memberikan pengganti untuk setiap pengeditan yang umum.

   Untuk menemukan pengeditan ini sebelum Anda mengalihkan lalu lintas produksi, jalankan pemeriksaan di [Periksa apakah kode Anda mengedit prefiks](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#how-to-tell-whether-your-integration-is-impacted) terhadap `claude-fable-5-2`. Di produksi, biarkan `prefix_mismatch_behavior` pada nilai default-nya, `"error"`, jika ketidakcocokan hanya bisa berarti ada bug di kode Anda. Untuk membuang blok yang terdampak dan melanjutkan tanpa penalaran tersebut selagi Anda memperbaiki pengeditannya, atur nilainya ke `"drop_block"` dengan beta header `thinking-binding-controls-2026-08-01`. Perlakukan itu sebagai solusi sementara, bukan pengaturan jangka panjang: [membuang blok dapat menaikkan token output](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#drop-block-cost).

3. **Claude Fable 5 tidak dapat membaca blok thinking Claude Fable 5.2:** Di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 membaca blok Claude Fable 5, sehingga percakapan yang berpindah dari `claude-fable-5` ke `claude-fable-5-2` tetap mempertahankan penalaran sebelumnya. Sebaliknya, Claude Fable 5 tidak dapat membaca blok Claude Fable 5.2. Jika peralihan router, percobaan ulang di sisi klien, atau [fallback penolakan classifier](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback) memindahkan percakapan dari Claude Fable 5.2 ke model lain, termasuk Claude Fable 5, API akan membuang blok yang tidak dapat dibaca oleh model tersebut. Permintaan berhasil, dan Anda tidak ditagih untuk token input yang dibuang. Dengan beta header `thinking-binding-controls-2026-08-01`, `input_transformations` mencantumkan setiap blok yang dibuang dengan `reason: "model_binding_mismatch"`. Lihat [Beralih model di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#switching-models).

4. **Gunakan toolset computer use sebagai pengganti `computer_20251124`:** Pada Claude Fable 5.2, entri `tools` bertipe `computer_20251124` mengembalikan error 400 di setiap platform kecuali Amazon Bedrock. Claude Fable 5 menerimanya dengan beta header-nya. Deklarasikan toolset `computer_toolset_20260801` sebagai gantinya, seperti yang dijelaskan di [Gunakan toolset computer use sebagai pengganti `computer_20251124`](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-computer-use).

5. **Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2:** Dengan [alat advisor](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool), yang masih dalam tahap beta, executor Claude Fable 5.2 hanya menerima Claude Fable 5.2 atau Claude Mythos 5.2 sebagai advisor-nya. Advisor lain yang diterima oleh executor Claude Fable 5, seperti Claude Fable 5 dan Claude Opus 5.5, mengembalikan error 400. Atur `model` advisor ke `claude-fable-5-2` atau `claude-mythos-5-2` saat Anda mengubah model executor. Lihat [Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-advisor-pairs).

### Daftar periksa migrasi

* Perbarui nama model dari `claude-fable-5` menjadi `claude-fable-5-2`.
* Periksa [batas laju](https://platform.claude.com/docs/id/api/rate-limits#rate-limits) Anda sebelum Anda memindahkan lalu lintas produksi. Claude Fable 5.2 memiliki batas lajunya sendiri, terpisah dari batas laju yang digunakan bersama oleh Claude Fable 5.1 dan Claude Fable 5.
* Ganti `tool_choice` paksa (`{type: "any"}` atau `{type: "tool", ...}`) dengan `{type: "auto"}` ditambah instruksi eksplisit dan alat `strict: true`, atau dengan output JSON. Letakkan instruksinya di giliran `user`. Ketika aplikasi Anda memerlukan pemanggilan tersebut, letakkan instruksinya di pesan `role: "system"` di tengah percakapan sebagai gantinya, pada platform yang dicantumkan di [Pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages). Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), penggunaan alat strict dan output JSON tidak tersedia untuk Claude Fable 5.2. Di sana, tetap gunakan `{type: "auto"}` dan instruksinya, serta validasi input alat di kode Anda.
* Jika kode Anda membangun array `messages` sendiri, jalankan sebuah sesi dengan beta header `thinking-binding-controls-2026-08-01` dan `prefix_mismatch_behavior: "drop_block"`, catat `input_transformations`, dan perbaiki setiap entri `prefix_binding_mismatch`. Entri `model_binding_mismatch` setelah peralihan model adalah hal yang wajar.
* Pertahankan riwayat agar append-only: bekukan `system` dan `tools` di awal sesi, lakukan perubahan di tengah sesi dengan pesan `role: "system"`, dan pangkas konteks di server. [Pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages) mencantumkan platform tempat fitur ini tersedia.
* Pilih `prefix_mismatch_behavior` untuk produksi: `"error"` (default), atau `"drop_block"` sebagai solusi sementara selagi Anda memperbaiki pengeditannya, karena [membuang blok dapat menaikkan token output](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#drop-block-cost). Pantau error 400 atau entri `input_transformations`.
* Tetap kirimkan kembali blok `thinking` tanpa perubahan di setiap giliran, termasuk yang kosong. Jika router atau fallback dapat memindahkan percakapan dari Claude Fable 5.2 ke Claude Fable 5, perkirakan Claude Fable 5 akan berjalan tanpa blok Claude Fable 5.2.
* Jika Anda memutar ulang percakapan tersimpan melalui akun yang berbeda, putar ulang masing-masing melalui akun yang menghasilkannya, atau akun yang terhubung dengannya. API membuang blok thinking Claude Fable 5.2 yang dihasilkan oleh akun lain. Lihat [Blok pemikiran tetap berada di akun yang menghasilkannya](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#account-bound-thinking).
* Jika Anda menggunakan computer use melalui `computer_20251124` di mana pun kecuali Amazon Bedrock, Claude Fable 5.2 mengembalikan error 400 untuk alat tersebut. Deklarasikan `computer_toolset_20260801` sebagai gantinya dan perbarui loop agen Anda untuk toolset tersebut.
* Jika Anda menggunakan alat advisor dengan Claude Fable 5.2 sebagai executor, atur `model` advisor ke `claude-fable-5-2` atau `claude-mythos-5-2`.
* Jika Anda mengubah effort di antara permintaan, pindahkan perubahan tersebut ke pesan `role: "system"` effort per pesan, yang masih dalam tahap beta, di mana platform Anda mendukungnya.
* Jika organisasi Anda memiliki komitmen Priority Tier, rencanakan kapasitas secara terpisah.
* Tangani `stop_reason: "refusal"` dan baca `stop_details.category`. Pertimbangkan `fallbacks: "default"`, yang masih dalam tahap beta di Claude API dan Claude Models on Google Cloud (Anthropic managed).
* Jalankan ulang [sweep effort](https://platform.claude.com/docs/id/build-with-claude/effort#recommended-effort-levels-for-claude-fable-5-2) pada eval Anda sendiri, dan tetapkan ulang baseline biaya dan latensi.
* Periksa prompt sistem, skill, dan instruksi lain yang Anda bawa terhadap [Tinjau prompt dan harness yang dirancang untuk model sebelumnya](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#review-instructions-written-for-earlier-models).

## Migrasi ke Claude Fable 5.2 dari Claude Opus 5

Claude Fable 5.2 menggunakan pola [Messages API](https://platform.claude.com/docs/id/build-with-claude/working-with-messages) dan [“tool use” (penggunaan alat)](https://platform.claude.com/docs/id/agents-and-tools/tool-use/overview) yang sama dengan [Claude Opus 5](https://platform.claude.com/docs/id/models/opus-5/overview). “Context window” (jendela konteks) 1M token, token output maksimum 128k, batas minimum “prompt caching” (caching prompt) 512 token, dan [pesan sistem di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/mid-conversation-system-messages) tetap berlaku. Demikian pula pembatasan pada prefill dan parameter sampling. Perbedaan berikut berlaku ketika Anda memindahkan lalu lintas, atau jalur fallback, ke Claude Fable 5.2.

### Perbarui nama model Anda

```python
model = "claude-opus-5"  # Before
model = "claude-fable-5-2"  # After
```

### Apa yang berubah

1. **Thinking tidak dapat dinonaktifkan:** Claude Opus 5 menerima `thinking: {type: "disabled"}` pada tingkat [effort](https://platform.claude.com/docs/id/build-with-claude/effort) `high` atau lebih rendah. Pada Claude Fable 5.2, [adaptive thinking](https://platform.claude.com/docs/id/build-with-claude/thinking) selalu aktif, dan `thinking: {type: "disabled"}` mengembalikan error 400 pada tingkat effort apa pun. Hapus field tersebut, dan kendalikan penggunaan token dengan tingkat effort yang lebih rendah. Untuk beban kerja yang berjalan dengan thinking dinonaktifkan, tinjau kembali `max_tokens`, yang mencakup thinking ditambah teks respons. Jika kode tersebut membaca konten berdasarkan posisi, seperti `content[0].text`, pilih blok konten berdasarkan `type` sebagai gantinya, karena blok `thinking` datang lebih dulu.

2. **Pilihan alat paksa mengembalikan error 400:** Claude Opus 5 menerima `tool_choice` `any` dan `tool`. Claude Fable 5.2 menolak keduanya. Lihat [Pilihan alat paksa mengembalikan error 400](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-forced-tool-choice) untuk apa yang harus dikirim sebagai gantinya.

3. **Mengedit giliran sebelumnya membatalkan validitas blok thinking, di setiap akun:** Claude Opus 5 tidak memeriksa apakah giliran sebelumnya berubah. Claude Fable 5.2 memeriksanya, untuk setiap akun. Jika kode Anda mengedit pesan sebelumnya, membangun ulang `system` atau `tools`, atau melakukan compaction di sisi klien di antara permintaan, Claude Fable 5.2 menolak permintaan tersebut atau membuang blok thinking yang tidak valid. Lihat [Mengedit giliran sebelumnya membatalkan validitas blok thinking](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-edited-history) untuk apa yang perlu diubah dan cara mengujinya.

4. **Claude Opus 5 tidak dapat membaca blok thinking Claude Fable 5.2:** Di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 membaca blok Claude Opus 5, sehingga percakapan yang berpindah dari `claude-opus-5` ke `claude-fable-5-2` tetap mempertahankan penalaran sebelumnya. Sebaliknya, Claude Opus 5 tidak dapat membaca blok Claude Fable 5.2. Percakapan yang berpindah dari Claude Fable 5.2 ke Claude Opus 5 menjalankan giliran setelah peralihan tanpa penalaran Claude Fable 5.2. API membuang blok tersebut sebelum model menerimanya, permintaan berhasil, dan blok yang dibuang tidak ditagih. Lihat [Beralih model di tengah percakapan](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#switching-models).

5. **Teks di antara pemanggilan alat dikembalikan dalam blok thinking:** Pada Claude Opus 5, teks yang ditulis model di antara pemanggilan alat dikembalikan sebagai blok `text`. Pada Claude Fable 5.2, narasi tersebut dikembalikan sebagai blok `thinking` pembaruan progres, paling banyak satu sebelum setiap pemanggilan alat. Jika antarmuka Anda menampilkan narasi tersebut, atur `thinking.display` ke `"updates"`, yang masih dalam tahap beta, untuk menerima pembaruan progres sebagai teks sementara penalaran tetap tersembunyi, atau ke `"summarized"` untuk menerima keduanya. Kemudian tampilkan blok `thinking` yang tidak kosong di antara blok `tool_use`. Lihat [Pembaruan progres di antara pemanggilan alat](https://platform.claude.com/docs/id/build-with-claude/thinking#progress-updates).

6. **Gunakan toolset computer use sebagai pengganti `computer_20251124`:** Claude Opus 5 menerima alat `computer_20251124` yang lebih lama dengan beta header-nya. Claude Fable 5.2 mengembalikan error 400 untuknya di setiap platform kecuali Amazon Bedrock. Lihat [Gunakan toolset computer use sebagai pengganti `computer_20251124`](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-computer-use).

7. **Classifier keamanan dan fallback:** Classifier keamanan Claude Fable 5.2 mencakup kumpulan kategori `stop_details` yang lebih luas dibandingkan classifier Claude Opus 5. Perkirakan adanya nilai `stop_details.category` tambahan, seperti `"bio"`. Tangani setiap kategori dalam [tabel kategori penolakan](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback#refusal-response). Untuk menjalankan ulang permintaan yang ditolak pada model lain, atur `fallbacks: "default"` atau buat mekanisme percobaan ulang Anda sendiri. Parameter tersebut masih dalam tahap beta di Claude API dan Claude Models on Google Cloud (Anthropic managed), serta memerlukan beta header `server-side-fallback-2026-07-01`. [Penolakan, fallback, dan penagihan](https://platform.claude.com/docs/id/models/fable-5-2/whats-new-fable-5-2#refusals-fallback-and-billing) mencantumkan target fallback yang diizinkan.

8. **Harga:** Claude Fable 5.2 dikenakan biaya $8 USD per juta token input dan $40 USD per juta token output, dibandingkan dengan $5 USD dan $25 USD untuk Claude Opus 5. Pembacaan cache prompt dikenakan $0,20 USD per juta token, dibandingkan dengan $0,50 USD. Lihat [Harga](https://platform.claude.com/docs/id/about-claude/pricing).

9. **Retensi data diwajibkan:** Claude Fable 5.2 memerlukan retensi data 30 hari dan tidak tersedia di bawah pengaturan “zero data retention” (retensi data nol), atau ZDR, kecuali secara tegas diizinkan oleh Anthropic. Claude Opus 5 tersedia di bawah ZDR. Di Claude API, permintaan dari organisasi atau workspace tanpa retensi 30 hari mengembalikan 400 `invalid_request_error`. Lihat [Persyaratan retensi data khusus model](https://platform.claude.com/docs/id/manage-claude/api-and-data-retention#model-specific-data-retention-requirements).

10. **Mode cepat:** Claude Opus 5 mendukung [mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode) (`speed: "fast"`) dalam pratinjau riset, dengan beta header `fast-mode-2026-02-01`. Claude Fable 5.2 mendukungnya dalam permintaan Messages API di Claude API tanpa header tersebut. Permintaan yang mengirimkan header tersebut tetap berfungsi. Mode cepat untuk Claude Fable 5.2 dikenakan biaya $16 USD per juta token input dan $80 USD per juta token output, dibandingkan dengan $10 USD dan $50 USD untuk Claude Opus 5 dalam mode cepat. Lihat [Harga mode cepat](https://platform.claude.com/docs/id/about-claude/pricing#fast-mode-pricing).

    Claude Fable 5.2 juga mendukung mode cepat di [Claude Models on Google Cloud (Google managed)](https://platform.claude.com/docs/id/build-with-claude/claude-models-on-google-cloud/google-managed), dengan pengaturan `speed: "fast"` yang sama.     Claude Fable 5.2 juga mendukung mode cepat di [Claude in Microsoft Foundry](https://platform.claude.com/docs/id/build-with-claude/claude-in-microsoft-foundry) untuk deployment yang di-hosting di Anthropic. Di sana, mode cepat merupakan model terpisah: kirim permintaan ke deployment `claude-fable-5-2-fast` dan jangan sertakan `speed`.

    Claude Mythos 5.2 juga mendukung mode cepat dalam permintaan Messages API di Claude API, tanpa header tersebut dan dengan harga mode cepat Claude Fable 5.2. [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan setiap platform tempat Claude Mythos 5.2 memiliki mode cepat.

    Hapus `speed: "fast"` di Claude Managed Agents. Hapus juga jika [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) tidak mencantumkan model yang Anda tuju.

11. **Output terstruktur dalam organisasi CMEK:** Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), Claude Opus 5 mendukung [output terstruktur](https://platform.claude.com/docs/id/build-with-claude/structured-outputs) dan Claude Fable 5.2 tidak. Hapus `strict: true` dan `output_config.format` dari permintaan yang Anda pindahkan, dan validasi output di kode Anda.

12. **Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2:** Dengan [alat advisor](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool), yang masih dalam tahap beta, executor Claude Opus 5 menerima beberapa advisor, di antaranya Claude Opus 5 dan Claude Fable 5.1. Executor Claude Fable 5.2 hanya menerima Claude Fable 5.2 atau Claude Mythos 5.2, dan advisor lain apa pun mengembalikan error 400. Atur `model` advisor ke `claude-fable-5-2` atau `claude-mythos-5-2` saat Anda mengubah model executor. Lihat [Executor Claude Fable 5.2 memerlukan advisor Claude Fable 5.2 atau Claude Mythos 5.2](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-advisor-pairs).

### Daftar periksa migrasi

* Jika organisasi Anda memiliki pengaturan ZDR, aktifkan retensi 30 hari untuk workspace, atau konfirmasikan kelayakan dengan tim akun Anthropic Anda, sebelum langkah lainnya.
* Perbarui ID model dari `claude-opus-5` menjadi `claude-fable-5-2`.
* Periksa [batas laju](https://platform.claude.com/docs/id/api/rate-limits#rate-limits) Anda sebelum memindahkan lalu lintas produksi. Batas laju Claude Fable 5.2 terpisah dari batas laju Claude Opus 5, dengan batas token yang lebih rendah di setiap tier.
* Hapus konfigurasi `thinking: {type: "disabled"}` apa pun. Kendalikan penggunaan token dengan tingkat effort yang lebih rendah, tinjau kembali `max_tokens`, dan pilih blok konten berdasarkan `type`.
* Kirimkan kembali blok `thinking` tanpa perubahan di setiap giliran, termasuk yang kosong. Dalam loop penggunaan alat, kirimkan kembali blok tersebut bersama hasil alat. Lihat [Mempertahankan blok pemikiran](https://platform.claude.com/docs/id/build-with-claude/thinking#preserving-thinking-blocks).
* Ganti `tool_choice` paksa (`any` atau `tool`) dengan `auto` ditambah instruksi eksplisit dan alat `strict: true`, atau dengan output JSON. Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), penggunaan alat strict dan output JSON tidak tersedia untuk Claude Fable 5.2. Di sana, tetap gunakan `auto` dan instruksinya, serta validasi input alat di kode Anda.
* Jika kode Anda membangun array `messages` sendiri, jalankan pemeriksaan di [Mengedit giliran sebelumnya membatalkan validitas blok thinking](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#fable-5-2-edited-history) terhadap `claude-fable-5-2`, perbaiki setiap entri `prefix_binding_mismatch`, dan pertahankan riwayat agar append-only.
* Jika Anda menggunakan computer use melalui `computer_20251124` di mana pun kecuali Amazon Bedrock, Claude Fable 5.2 mengembalikan error 400 untuk alat tersebut. Deklarasikan `computer_toolset_20260801` sebagai gantinya dan perbarui loop agen Anda untuk toolset tersebut.
* Jika Anda menggunakan alat advisor dengan Claude Fable 5.2 sebagai executor, atur `model` advisor ke `claude-fable-5-2` atau `claude-mythos-5-2`.
* Jika router atau fallback memindahkan percakapan dari Claude Fable 5.2 ke Claude Opus 5, perkirakan giliran setelah peralihan akan berjalan tanpa blok thinking Claude Fable 5.2.
* Jika Anda memutar ulang percakapan tersimpan melalui akun yang berbeda, putar ulang masing-masing melalui akun yang menghasilkannya, atau akun yang terhubung dengannya. API membuang blok thinking Claude Fable 5.2 yang dihasilkan oleh akun lain. Lihat [Blok pemikiran tetap berada di akun yang menghasilkannya](https://platform.claude.com/docs/id/build-with-claude/preserved-thinking#account-bound-thinking).
* Jika antarmuka Anda menampilkan teks di antara pemanggilan alat, atur `thinking.display` ke `"updates"`, yang masih dalam tahap beta, atau ke `"summarized"`, dan tampilkan blok `thinking` yang tidak kosong.
* Tangani setiap `stop_details.category`. Jika Anda menetapkan daftar `fallbacks` eksplisit, sebutkan hanya target yang diizinkan untuk Claude Fable 5.2.
* Jika Anda menggunakan mode cepat dalam permintaan Messages API di Claude API, pertahankan `speed: "fast"` hanya jika [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan model yang Anda tuju. Jika Anda mempertahankannya, tetapkan ulang baseline biaya terhadap [harga mode cepat](https://platform.claude.com/docs/id/about-claude/pricing#fast-mode-pricing). Hapus `speed: "fast"` di Claude Managed Agents. Anda tidak memerlukan beta header `fast-mode-2026-02-01`, dan permintaan yang mengirimkannya tetap berfungsi.
* Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), hapus `strict: true` dan `output_config.format`, dan validasi output di kode Anda.
* Jalankan ulang [sweep effort](https://platform.claude.com/docs/id/build-with-claude/effort#recommended-effort-levels-for-claude-fable-5-2) pada eval Anda sendiri, dan tetapkan ulang baseline biaya dan latensi.
* Periksa prompt sistem, skill, dan instruksi lain yang Anda bawa terhadap [Tinjau prompt dan harness yang dirancang untuk model sebelumnya](https://platform.claude.com/docs/id/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#review-instructions-written-for-earlier-models).

## Migrasi ke Claude Fable 5.2 dari Claude Opus 4.8 atau sebelumnya

Pertama, kerjakan [Migrasi ke Claude Fable 5.2 dari Claude Opus 5](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#migrating-from-claude-opus-5-to-claude-fable-5-2), dengan `claude-opus-4-8` sebagai ID model yang Anda ganti. Bagian tersebut berlaku sebagaimana tertulis untuk kode pada Claude Opus 4.8, karena Claude Opus 4.8, seperti Claude Opus 5:

* Menerima `thinking: {type: "disabled"}`, pilihan alat paksa, alat `computer_20251124`, dan fast mode.
* Mengembalikan teks di antara pemanggilan alat sebagai blok `text`.
* Tersedia di bawah pengaturan retensi data nol (ZDR).
* Dikenakan biaya $5 USD per juta token input dan $25 USD per juta token output, dengan pembacaan cache prompt sebesar $0,50 USD.

Bagian ini menambahkan perbedaan yang tidak dicakup oleh bagian Claude Opus 5.

### Apa yang berubah

1. **Thinking berjalan pada permintaan yang tidak menyertakannya:** Pada Claude Opus 4.8, thinking nonaktif kecuali Anda memintanya. Pada Claude Fable 5.2, permintaan tanpa field `thinking` berjalan dengan adaptive thinking. Respons dapat berisi blok `thinking` sebelum blok `text`, jadi pilih blok konten berdasarkan `type` alih-alih membaca `content[0].text`. Dalam loop penggunaan alat, kirimkan kembali blok `thinking` tanpa perubahan bersama hasil alat, termasuk yang kosong. Token thinking ditagih sebagai token output, dan `max_tokens` mencakup thinking ditambah teks respons. Tinjau kembali `max_tokens`, dan turunkan `effort` di mana Anda menginginkan lebih sedikit thinking. Di Claude API dan Claude Models on Google Cloud (Google managed), Claude Fable 5.2 membaca blok thinking dari giliran Claude Opus 4.8 sebelumnya, sehingga percakapan yang berpindah ke `claude-fable-5-2` tetap mempertahankan penalaran tersebut.

2. **Batas minimum caching prompt lebih rendah:** Panjang prompt minimum yang dapat di-cache pada Claude Fable 5.2 adalah 512 token, turun dari 1.024 token pada Claude Opus 4.8. Prompt yang sebelumnya terlalu pendek untuk di-cache kini dapat membuat entri cache, tanpa memerlukan perubahan kode. Lihat [Caching prompt](https://platform.claude.com/docs/id/build-with-claude/prompt-caching#cache-limitations).

3. **Priority Tier tidak didukung:** Claude Opus 4.8 mendukung [Priority Tier](https://platform.claude.com/docs/id/api/service-tiers#supported-models). Claude Fable 5.2 tidak. Jika organisasi Anda memiliki komitmen Priority Tier, rencanakan kapasitas secara terpisah.

4. **Saran dari alat advisor dikembalikan dalam keadaan terenkripsi:** Dengan [alat advisor](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool), yang masih dalam tahap beta, executor Claude Opus 4.8 dapat dipasangkan dengan advisor yang mengembalikan sarannya sebagai plaintext, seperti Claude Opus 4.8. Satu-satunya advisor yang diterima executor Claude Fable 5.2, yaitu Claude Fable 5.2 dan Claude Mythos 5.2, mengembalikan saran dalam keadaan terenkripsi, sebagai blok `advisor_redacted_result`, sehingga klien Anda tidak dapat membaca teksnya. Jika kode Anda membaca teks saran, hapus ketergantungan tersebut. Lihat [Varian hasil](https://platform.claude.com/docs/id/agents-and-tools/tool-use/advisor-tool#result-variants).

Jika kode Anda menggunakan Claude Opus 4.7 atau sebelumnya, terapkan juga sebagian dari daftar periksa migrasi panduan Claude Opus 5.5. Mulailah dari kelompok [Claude Opus 4.7 atau sebelumnya](https://platform.claude.com/docs/id/models/opus-5-5/migration-guide#migration-checklist-from-claude-opus-47) dan terapkan setiap kelompok setelahnya secara berurutan, hingga dan termasuk kelompok yang menyebutkan model Anda. Kelompok-kelompok ini mencakup perubahan permintaan yang dibuat sebelum Claude Opus 4.8, seperti parameter sampling dan beta header yang dihapus. Terapkan item mode cepat dari daftar periksa tersebut hanya jika [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan model yang Anda tuju. Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), output terstruktur tidak tersedia untuk Claude Fable 5.2, jadi jangan terapkan item `output_config.format` di sana. Hapus `output_format` dari permintaan Anda sebagai gantinya, dan validasi JSON di kode Anda.

### Daftar periksa migrasi

* Kerjakan [daftar periksa Claude Opus 5](https://platform.claude.com/docs/id/models/fable-5-2/migration-guide#migration-checklist-fable-5-2-from-opus-5), dengan `claude-opus-4-8` sebagai ID model yang Anda ganti.
* Tinjau beban kerja yang berjalan tanpa field `thinking`. Pada Claude Fable 5.2, beban kerja tersebut berjalan dengan thinking, jadi tinjau kembali `max_tokens`, turunkan `effort` di mana Anda menginginkan lebih sedikit thinking, dan pilih blok konten berdasarkan `type`.
* Periksa bahwa kode apa pun yang mengurai field `thinking` memperlakukannya hanya sebagai teks tampilan. Atur `thinking.display` ke `"summarized"` untuk menerima ringkasan yang dapat dibaca.
* Tinjau prompt yang mendekati batas minimum caching: prompt dengan 512 token atau lebih dapat membuat entri cache.
* Jika organisasi Anda memiliki komitmen Priority Tier, rencanakan kapasitas secara terpisah.
* Jika Anda menggunakan alat advisor dan kode Anda membaca teks saran, hapus ketergantungan tersebut: saran tiba sebagai blok `advisor_redacted_result` yang terenkripsi.
* Jalankan sweep effort baru pada eval Anda sendiri alih-alih membawa pengaturan yang disetel untuk Claude Opus 4.8.
* Pada Claude Opus 4.7 atau sebelumnya, terapkan juga kelompok daftar periksa panduan Claude Opus 5.5 untuk model Anda. Lewati item mode cepat kecuali [Ketersediaan mode cepat](https://platform.claude.com/docs/id/build-with-claude/fast-mode#feature-availability) mencantumkan model yang Anda tuju. Dalam organisasi dengan [kunci enkripsi yang dikelola pelanggan](https://platform.claude.com/docs/id/manage-claude/cmek), lewati juga item `output_config.format` dan hapus `output_format` dari permintaan Anda.
