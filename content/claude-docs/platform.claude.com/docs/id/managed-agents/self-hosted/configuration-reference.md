Halaman ini menunjukkan tempat pengaturan server Claude Managed Agents yang di-host sendiri disimpan, dan mencantumkannya. Untuk menyiapkan fitur, lihat [Single sign-on](https://platform.claude.com/docs/id/managed-agents/self-hosted/configure), [Identitas dan kredensial agen](https://platform.claude.com/docs/id/managed-agents/self-hosted/agent-identity), dan [Penyedia inferensi](https://platform.claude.com/docs/id/managed-agents/self-hosted/inference-provider).

## Tempat pengaturan disimpan

Server membaca pengaturannya dari satu file YAML, dan kredensialnya dari lingkungannya.

* **Docker Compose:** File tersebut adalah `compose.config.yaml`, di samping `docker-compose.yml` di dalam arsip yang diekstrak. Edit file tersebut, lalu jalankan `docker compose restart cma-server` dari direktori tersebut.
* **Kubernetes:** File tersebut adalah nilai `server.config` dari Helm chart server. Edit nilai tersebut di file values Anda, jalankan `helm upgrade`, lalu restart server dengan `kubectl -n cma-server rollout restart deployment -l anthropic.com/role=server`. Lihat [Menerapkan di Kubernetes](https://platform.claude.com/docs/id/managed-agents/self-hosted/kubernetes).

Jika server menolak pengaturan yang ditunjukkan oleh halaman-halaman yang di-host sendiri, [upgrade server](https://platform.claude.com/docs/id/managed-agents/self-hosted/upgrade). `cma-server.example.yaml`, di tingkat teratas arsip, memberi anotasi pada kunci-kunci umum.

Kredensial tidak pernah dimasukkan ke dalam file. Server membacanya dari variabel lingkungan, atau dari identitas yang dilekatkan cloud Anda ke host.

### Meneruskan kredensial ke stack Compose

Di stack Compose, container server hanya menerima variabel yang ada di daftar `environment:` dari layanan `cma-server` di `docker-compose.yml`. Untuk meneruskan variabel lain:

1. Tambahkan namanya ke daftar tersebut, dan tetapkan nilainya di `.env`.
2. Jika kredensial berupa file, letakkan file tersebut di samping `docker-compose.yml`, dan tambahkan baris seperti `- ./gcp-key.json:/etc/cma-server/gcp-key.json:ro` ke daftar `x-server-mounts` di `docker-compose.yml`. Path setelah titik dua pertama adalah path file di dalam container. Gunakan path tersebut sebagai nilai variabel di `.env`, atau sebagai nilai pengaturan yang menyebutkan file tersebut.
3. Jalankan `docker compose up -d`. Restart tidak membaca ulang `.env`.

Upgrade menggantikan `docker-compose.yml`, jadi ulangi pengeditan ini di file rilis baru sebelum Anda memulai stack-nya.

## Cara membaca tabel

Setiap pengaturan memiliki kunci di [file pengaturan](https://platform.claude.com/docs/id/managed-agents/self-hosted/configuration-reference#where-settings-go), dan sebagian besar pengaturan juga memiliki “environment variable” (variabel lingkungan). Variabel menimpa file, dan file menimpa default. Server tidak akan dimulai jika file pengaturannya memiliki kunci yang tidak dikenal, dan pesan kesalahannya menyebutkan lokasi kunci tersebut.

* **Kunci:** Setiap titik dalam kunci adalah satu tingkat penyarangan di dalam file. Misalnya, `server.addr` adalah kunci `addr` di bagian `server`.
* **Variabel:** Nama variabel adalah `CMA_` lalu kunci dalam huruf kapital, dengan dua garis bawah sebagai pengganti setiap titik.
* **Hanya file:** Pengaturan tidak memiliki variabel.
* **Hanya lingkungan:** Server tidak akan dimulai jika pengaturan ada di dalam file.
* **Hanya `bedrock`, dan label serupa:** Pengaturan hanya berfungsi dengan penyedia, store, atau pengelola rahasia tersebut. Jika Anda menetapkannya saat menggunakan yang lain, server tidak akan dimulai.
* **Daftar:** Daftar adalah daftar YAML di dalam file, dan string yang dipisahkan koma di dalam variabel.
* **Durasi:** Durasi adalah angka dengan satuan, seperti `30s`, `5m`, atau `1h`.
* **Bilangan bulat:** Bilangan bulat adalah digit biasa, tanpa tanda, nol di depan, atau garis bawah.

Saat startup, server mencatat di log pengaturan yang Anda tetapkan dan sebagian besar default, masing-masing beserta asal nilainya, seperti `server.addr=0.0.0.0:8400 (file)`. Server mencatat `***` sebagai pengganti rahasia, kecuali kunci API server yang dibuatnya sendiri.

## Penyedia inferensi

Untuk menyiapkan penyedia, lihat [Penyedia inferensi](https://platform.claude.com/docs/id/managed-agents/self-hosted/inference-provider).

| Pengaturan<br />Variabel lingkungan                                  | Default     | Deskripsi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `inference.provider`<br />`CMA_INFERENCE__PROVIDER`                  | `anthropic` | Tempat server mengirim panggilan model. Nilainya adalah `anthropic`, `bedrock`, `vertex`, `foundry`, dan `gateway`.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `inference.headers`<br />Hanya file                                  | Tidak ada   | Header permintaan yang ditambahkan server ke setiap panggilan model, sebagai map dari nama header ke nilai. Beri tanda kutip pada setiap nilai. Server menolak untuk dimulai pada nilai tanpa tanda kutip yang tidak dibaca YAML sebagai teks, seperti `true` atau `0042`. Dengan `gateway`, nilai juga dapat berupa `{ from: request_id }` atau `{ from: session_id }`.                                                                                                                                                                                     |
| `inference.model_fallback`<br />`CMA_INFERENCE__MODEL_FALLBACK`      | `true`      | Hanya `anthropic`. Apakah panggilan model meminta [fallback sisi server](https://platform.claude.com/docs/id/build-with-claude/refusals-and-fallback#server-side-fallback). Panggilan tersebut membawa field `fallbacks` dan header `anthropic-beta: server-side-fallback-2026-07-01`. Proxy yang Anda sebutkan di `ANTHROPIC_BASE_URL` mungkin menolak field atau header tersebut. Jika proxy menjawab dengan `400` atau `422`, server mengirim panggilan tersebut lagi tanpa keduanya.                                                                     |
| `inference.metadata.user_id`<br />`CMA_INFERENCE__METADATA__USER_ID` | Tidak ada   | Hanya `anthropic` dan `foundry`, atau `gateway` dengan `format: anthropic-messages`. Satu pengidentifikasi yang dikirim server sebagai `metadata.user_id` bersama setiap panggilan model. Log startup mencetaknya. Tanpa pengaturan ini, server mengirim label `cma-server`. Anda tidak dapat menonaktifkan `metadata.user_id`. Jika penyedia atau proxy menolaknya, setiap panggilan model akan gagal. Lihat [Apa yang keluar dari jaringan Anda](https://platform.claude.com/docs/id/managed-agents/self-hosted-data-and-access#what-leaves-your-network). |

| `git.max_session_transfer_bytes`<br />`CMA_GIT__MAX_SESSION_TRANSFER_BYTES` | `8589934592` (8 GiB)    | Jumlah lalu lintas Git terbanyak, dalam byte, yang dibawa satu server untuk satu sesi, unggahan dan unduhan digabungkan. Batasan berikut berlaku untuk repositori Git:

* **Protokol:** Server tidak mendukung SSH atau Git LFS, dan server menolak redirect, seperti redirect untuk repositori yang diganti namanya.
* **Token:** Host Git harus menerima token sebagai kata sandi autentikasi HTTP Basic, dengan nama pengguna `x-access-token`.
* **URL:** URL repositori memiliki satu pemilik dan satu nama repositori, sehingga Anda tidak dapat menggunakan repositori di subgrup GitLab.
* **Host:** Untuk URL di host yang tidak dicantumkan oleh `git.allowed_hostnames`, server mengembalikan `400`. Pesan kesalahannya menyatakan bahwa URL harus berada di `github.com`, bahkan jika Anda mencantumkan host lain.
* **Push:** Server selalu menolak push yang menghapus branch, atau yang mengubah apa pun selain branch, seperti tag.

Seberapa sering server dengan slot giliran kosong mencari pekerjaan yang menunggu di database. Minimumnya adalah `50ms`.                                                                                                                                                                             |
| `scheduler.sandbox_claim`<br />`CMA_SCHEDULER__SANDBOX_CLAIM`                   | `immediate` | Kapan worker dapat memulai sandbox sesi. `immediate` berarti segera setelah sesi dibuat, sehingga panggilan alat pertama menunggu paling singkat. `tool_call` berarti pada panggilan alat pertama sesi yang memerlukan sandbox, sehingga sesi yang tidak melakukan panggilan semacam itu tidak menggunakan sandbox.                   |
| `limits.model_call_timeout`<br />`CMA_LIMITS__MODEL_CALL_TIMEOUT`               | `20m`       | Berapa lama satu panggilan model dapat berjalan, termasuk percobaan ulang, sebelum server membatalkannya.                                                                                                                                                                                                                             |
| `limits.stream_idle_timeout`<br />`CMA_LIMITS__STREAM_IDLE_TIMEOUT`             | `5m`        | Berapa lama respons panggilan model dapat tidak mengirimkan apa pun sebelum server menghentikan percobaan tersebut.                                                                                                                                                                                                                   |
| `limits.mcp_call_timeout`<br />`CMA_LIMITS__MCP_CALL_TIMEOUT`                   | `4m`        | Berapa lama satu panggilan alat MCP dapat berjalan sebelum server menghentikannya.                                                                                                                                                                                                                                                    |

## Model dan compaction

| Pengaturan<br />Variabel lingkungan   | Default                                       | Deskripsi                                                                                                                                                                                     |
| ------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `models.settings`<br />Hanya file     | Tidak ada                                     | Perubahan pada katalog model bawaan server, dengan kunci ID model. Lihat [Entri model](https://platform.claude.com/docs/id/managed-agents/self-hosted/configuration-reference#model-entries). |
| `compaction.triggers`<br />Hanya file | Sekitar 90% dari jendela konteks setiap model | Ukuran konteks, dalam token, saat sebuah giliran pada suatu model memadatkan riwayatnya, dengan kunci ID model. Minimumnya adalah `50000`. Setiap model harus mendukung compaction.           |

### Entri model

Setiap entri `models.settings` mengubah model di katalog atau menambahkan model baru. Untuk model di katalog, field yang Anda hilangkan mempertahankan nilai bawaannya.

| Field                          | Deskripsi                                                                                                                                                                                                                                                              |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fast_supported`               | Apakah model menerima `speed: "fast"`. Wajib untuk model yang Anda tambahkan.                                                                                                                                                                                          |
| `inference_geo_supported`      | Apakah model menerima `inference_geo`.                                                                                                                                                                                                                                 |
| `forced_tool_choice_supported` | Apakah model menerima permintaan yang memaksanya memanggil satu alat. Server mengirim permintaan semacam itu hanya untuk menjalankan panggilan `web_search` atau `web_fetch` yang telah disetujui. Dengan `false`, server tidak pernah memaksakan alat pada model ini. |
| `effort_supported`             | Apakah model menerima tingkat effort.                                                                                                                                                                                                                                  |
| `effort_levels`                | Tingkat effort yang diterima model, dari `low`, `medium`, `high`, `xhigh`, dan `max`. Wajib dengan `effort_supported: true` pada model tanpa tingkat bawaan.                                                                                                           |
| `effort_default`               | Tingkat effort sesi yang agennya tidak menyebutkan tingkat apa pun. Harus salah satu dari `effort_levels`. Wajib dengan `effort_supported: true` pada model tanpa default bawaan.                                                                                      |
| `thinking`                     | Mode thinking yang diminta server, `enabled` atau `adaptive`.                                                                                                                                                                                                          |
| `thinking_budget`              | Anggaran thinking, dalam token, yang dikirim server dengan `thinking: enabled`.                                                                                                                                                                                        |
| `max_tokens`                   | Nilai `max_tokens` dari setiap panggilan model.                                                                                                                                                                                                                        |
